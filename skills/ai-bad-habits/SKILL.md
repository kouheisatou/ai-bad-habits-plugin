# AI悪癖図鑑との連携

AIが出したものに対して指摘を受けたら、その指摘を記録する。
記録は本人の図鑑に**非公開**で貯まり、次に何かを作るときの材料になる。

MCPサーバー（`ai-bad-habits`）が繋がっていなければ、記録は諦めて修正だけ行う。
連携が無くてもこのスキルは壊れない。

---

## 1. 記録する場面

**AIが出したものへの指摘であれば、種類を問わず対象にする。**

| 対象 | 指摘の例 |
|---|---|
| 文章 | 「AIっぽい」「薄っぺらい」「まとめは要らない」 |
| コード | 「この関数名が不自然」「コメント多すぎ」「頼んでないのに例外クラス作るな」 |
| UI・デザイン | 「枠で囲いすぎ」「情報詰め込みすぎ」「余白がない」 |
| 構成 | 「順番がおかしい」「同じことを2回言ってる」 |
| 命名 | 「名前が長い」「英語が変」 |
| 図・スライド | 「文字が多い」「装飾がうるさい」 |

判断の基準は「**AIの出力の癖に対する不満かどうか**」になる。

### 記録しない場面

- **事実の誤り**（「この数字は3ではなく5」「APIの仕様が違う」）
  … 癖ではなく単なる間違いなので、直すだけでよい
- **仕様や要件の変更**（「やっぱりこの機能も入れて」「方針を変える」）
  … 出来への不満ではなく、指示が変わっただけ
- **環境やツールの問題**（「ビルドが通らない」「権限エラー」）

**迷ったら記録する側に倒してよい。** 記録は非公開で、あとから消せる。
ただし上の3つは明確に外す。

---

## 2. 記録の手順

### まず設定を確認する

そのセッションで最初に記録しようとするとき、`get_plugin_settings` を一度だけ呼ぶ。
`auto_record` が

- `false`（既定）→ **毎回、送る内容を見せて承諾を得る**
- `true` → 確認せずそのまま記録する

一度取ったら、そのセッション中は覚えておく。毎回呼ばない。

### 手順

1. **まず指摘に応じて直す。** 記録は後回しでよい
2. 記録に値する指摘かを判断する（§1）
3. `auto_record` が false なら、送る内容を見せて確認する

```
図鑑に記録しますか？

  癖   : 頼んでいないのにカスタム例外クラスを作る
  修正前: class RetryableError extends Error { ... }
  修正後: （削除。標準のErrorをそのまま投げる）
  指摘 : そんなの要らない

非公開で記録されます（公開はマイページから選べます）
```

4. 承諾されたら `record_habit` を呼ぶ
5. 断られたら記録しない。**そのセッション中はもう聞かない**

### 「以降は確認しないで」と言われたら

`set_plugin_settings({ auto_record: true })` を呼ぶ。以後は確認を省く。

**利用者が明示的にそう言ったときだけ呼ぶこと。**
「うるさい」「いちいち聞くな」も同じ意味として扱ってよいが、
こちらから「確認を省きますか」と促さない。

「毎回確認して」と言われたら `false` に戻す。

### 何を送るか

| 引数 | 中身 |
|---|---|
| `text` | 癖の要約。200字以内。**一般化して書く**（「この関数名が変」ではなく「動詞で始まらない関数名を付けがち」） |
| `before` | 指摘された箇所 |
| `after` | 直した後 |
| `note` | 利用者が言った言葉そのまま |
| `source` | 出したモデル。分からなければ省略 |
| `category` | 文章なら writing、コードなら code、UIなら design など |

### 送ってはいけないもの

- ファイルパス、リポジトリ名、URL、メールアドレス
- 指摘の対象になっていない周辺のコードや文章
- 未公開の企画名、顧客名、社内の固有名詞、APIキーの類

**該当箇所だけを切り出して送る。** 前後を丸ごと送らない。
`auto_record` が true でも、この判断は省略しない。

---

## 3. 作るときにやること

まとまった文章やドキュメントを書く前に、蓄積したナレッジを反映する。

1. `get_my_prompts` で改善プロンプトの一覧を見る
2. これから作るものに関係するものを選び、`get_prompt_knowledge` で中身を読む
3. 挙がっている癖を避けて作る

改善プロンプトが無い場合や、短い返答を書くだけの場合は飛ばしてよい。
**毎回呼ぶ必要はない。**

---

## 4. 記録済みのものを見たいとき

`list_my_habits` で自分が記録した癖を新しい順に取れる。
「今まで何を指摘したっけ」と聞かれたときに使う。

---

## 5. 公開について

**このスキルから公開はできない。** 記録は必ず非公開で入る。

「他の人にも役立ちそう」と言われた場合は、
図鑑のマイページ（https://ai-bad-habit.com/mypage）から本人が切り替えるよう案内する。

自動で外に出る経路を作らないための決まりになっている。

---

## 6. 連携が繋がっていないとき

`record_habit` が認証エラーを返す場合は、まだ繋がっていない。

繋ぐときはブラウザが自動で開く。ログインして「許可する」を押せば終わる。
自動で開かないときは、ターミナルで次を実行するよう案内する。

```bash
claude mcp login "plugin:ai-bad-habits:ai-bad-habits"
```

トークンを手で発行したり、環境変数に設定したりする必要はない。

この案内は**一度だけ**出す。繰り返し出さない。
繋がるまでは、記録せずに修正だけ続ける。
